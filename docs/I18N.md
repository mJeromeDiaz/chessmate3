# Langues — Don't Stay Rooky

> Chemins relatifs à `front/` (sauf mention de `api/`).

Le site est en **français** et en **anglais** (choix du 2026-10-14). Le français est la langue
**source** : tous les textes sont écrits d'abord en français ; l'anglais (et les langues à venir)
sont traduits à partir de lui.

## 1. Règles validées (2026-10-14)

- **Langue d'une première visite** : la première des langues du navigateur que le site parle
  (`fr-CA` → français) ; sinon l'**anglais**, langue par défaut.
- **Choix du joueur** : un menu « FR / EN » dans l'en-tête de la landing, un sélecteur dans le
  profil (« Préférences »). Le choix est gardé dans le navigateur (`dontstayrooky.locale`, appliqué
  avant le premier affichage) et, connecté, sur le compte (`app_user.locale`, `PUT
  /api/profile/locale`), comme le thème : le choix du compte l'emporte au chargement du profil ; un
  compte sans choix reçoit celui du navigateur.
- **Texte manquant** : une clé absente d'une langue s'affiche en français (`fallbackLocale`), sans
  avertissement dans la console.
- Ce qui vient de la base (offres de la boutique, positions d'évaluation, noms d'ouvertures et de
  thèmes) n'est pas traduit pour l'instant.
- Lots : F0 socle, F1 à F8 front par domaine, puis l'API (A1 langue côté serveur, A2 emails, A3
  notifications, messages, export, calendrier).

## 2. Organisation

| Élément | Emplacement |
|---|---|
| Instance, langues, `t()` hors composant, `intlLocale()`, `browserLocale()` | `src/i18n/index.js` |
| Messages | `src/i18n/<langue>/<domaine>.json` : le fichier `fr/woodpecker.json` donne les clés `woodpecker.*` |
| Langue courante (navigateur, compte, Quasar, `<html lang>`) | `src/stores/locale.js`, appliquée par `src/boot/i18n.js` |
| Sélecteurs | `components/theme/LocaleMenu.vue` (landing), `components/profile/LocaleSection.vue` (profil) |
| API | `App\Enum\Locale`, `App\Entity\User::$locale`, `App\Dto\Profile\LocaleRequest`, `ProfileController::setLocale` (migration `Version20261021090000`), `locale` dans `GET /api/profile` et l'export |

Dans un composant : `const { t } = useI18n()` puis `t('domaine.cle')` ; dans un store ou un
utilitaire : `import { t } from '@/i18n'`. Pluriels (syntaxe vue-i18n) : `"aucun puzzle | 1 puzzle
| {n} puzzles"` et `t('cle', n)`. Les messages JSON sont précompilés par
`@intlify/unplugin-vue-i18n` (`quasar.config.js`, `include: src/i18n/**/*.json` : surtout pas `index.js`, que le plugin prendrait pour un fichier de messages et refuserait).

Dates et nombres : toujours `Intl` avec `intlLocale()` (`fr-FR`, `en-GB` : jour avant le mois et
horloge sur 24 h dans les deux langues), jamais une langue écrite en dur. Les composants Quasar
(boutons des fenêtres, calendriers) suivent la langue (`quasar/lang/fr`, `en-GB`).

## 3. Traduire

1. Ajouter ou compléter `src/i18n/en/<domaine>.json` avec les mêmes clés que `fr/<domaine>.json`.
2. `npm run i18n:missing` liste, fichier par fichier, les clés à traduire (et celles qui ne
   servent plus) ; `npm run i18n:missing -- en` pour une seule langue. Code de sortie 1 tant qu'il
   en manque.

Ajouter une langue : son code dans `LOCALES`, son nom dans `LOCALE_NAMES`, sa balise `Intl` et son
paquet Quasar (`stores/locale.js`), son cas dans `App\Enum\Locale`, puis le dossier
`src/i18n/<code>/`.

## 4. Tests

- Vitest tourne en français (`tests/unit/setup.js`) : les tests attendent les textes source.
  `tests/unit/i18n.test.js` : langue du navigateur, balises `Intl`, repli sur le français.
- Playwright simule un navigateur français (`locale: 'fr-FR'`, `playwright.config.js`) ;
  `tests/e2e/profile.spec.js` change la langue dans le profil (enregistrée, `<html lang>`).
- PHPUnit : `tests/Functional/Profile/LocaleTest.php`.
